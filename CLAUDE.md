# Проект: Назначение Иванюк В.С. руководителем проектно-конструкторского отдела

Knowledge base проекта. Цель — провести назначение **Иванюк Валентины Сергеевны**
на должность **ведущего инженера-конструктора** и **руководителя проектно-конструкторского отдела** ООО «АльденаГрупп» (Брест, РБ) «без сучка и
задоринки»: оформить все кадровые документы, легитимизировать полномочия,
представить коллективу и наладить работу отдела.

## Что отвечает Иванюк В.С. в новой роли
- Всецело отвечает за чертежи отдела, **проверяет (нормоконтроль)** чертежи.
- **Распределяет работу** между конструкторами и архитектором, контролирует сроки.
- Доводит и контролирует исполнение **Регламента КМД**, **обучает новичков**.
- Ведёт документы руководителя: **табель учёта рабочего времени, график отпусков**,
  реестр объектов и сроков, журналы задач и проверки чертежей, отчётность.

## Структура проекта (где что лежит)
| Папка | Содержимое |
|---|---|
| `00_Исходные_данные/` | Реквизиты, ФИО, состав отдела — **единый источник истины** |
| `01_Кадровые_документы/` | Представление, приказы, аттестация (положение, приказы, характеристика-отзыв), должностная инструкция, допсоглашение, лист ознакомления, информационное письмо |
| `02_Положение_об_отделе/` | Положение о проектно-конструкторском отделе |
| `03_Внедрение_и_коллектив/` | План внедрения 30/60/90, сценарий представления, протокол собрания, онбординг, чек-лист контрольных точек |
| `04_Шаблоны_управления_отделом/` | Табель, график отпусков, журналы задач и проверки, реестр объектов, отчёт, акт приёма-передачи дел, памятка нормоконтроля |
| `05_Регламент_конструкторов/` | Готовый регламент КМД (исходник `.docx` + текст) |
| `scripts/` | `build_docx.py` — генерирует `.docx` из `.md` |
| `_build/docx/` | Сгенерированные `.docx` (готовые к печати/подписи) |
| `ROADMAP_внедрения.md` | Pipeline внедрения: этапы, чек-листы, ответственные, сроки |

## Правила работы с проектом (conventions)
- **Единый источник данных** — `00_Исходные_данные/Данные_проекта.md`. Реквизиты,
  ФИО, даты, состав отдела правим только там, затем перегенерируем `.docx`.
- Каждый документ существует в двух видах: `.md` (редактируемый исходник) и
  `.docx` (готовый к подписи). `.docx` — производное, руками не правим, а
  перегенерируем: `python scripts/build_docx.py`.
- Правовое поле — **Трудовой кодекс Республики Беларусь**. Не использовать нормы РФ.
- Все формулировки про чертежи/ведомости/спецификации согласованы с
  **Регламентом КМД** (раздел и пункт указываются явно).

## Pipeline внедрения (кратко)
1. Подготовка документов (этот проект) → 2. Аттестация → 3. Подписание приказов →
4. Ознакомление сотрудника и отдела, передача дел по акту → 5. Представление
коллективу и постановка задач → 6. Запуск инструментов руководителя (табель,
график, журналы) → 7. Контроль первых 30/60/90 дней по чек-листу.
Подробно — в `ROADMAP_внедрения.md`.

## Ключевые развилки, уже решённые (не менять без запроса пользователя)
- Приказы издаёт и ДИ/Положение утверждает **директор** (Калита А.В.);
  заместитель директора (Покалюк Д.Г.) — подписывает представления,
  характеристику-отзыв, принимает табель/график/отчёты.
- Перевод оформляется по цепочке: аттестация → заявление работника →
  штатное расписание → приказ о переводе (ст. 30 ТК РБ) → допсоглашение.

## Как перегенерировать документы
```
python scripts/build_docx.py        # собрать все .docx в _build/docx/
```
